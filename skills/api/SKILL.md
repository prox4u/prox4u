# Prox4u — Contrat API REST

> 📖 **Notice utilisateur (module InfluxDB 3 Core)** : module « Documentation » de l'app — route `/docs/influxdb`, source `packages/web/src/plugins/docs/content/influxdb.md`.

Serveur Fastify (`packages/server`), HTTPS :8080 en prod. Modules : `modules/dashboard/routes.ts`, `modules/supervision/routes.ts`, enregistrés dans `modules/index.ts`.

## 1. Règles générales
- **Cache 5 min** (mémoire, par clé) sur les endpoints lourds ; pas de cache sur `/api/health`, `/api/dashboard`, `/api/endpoints` (snapshot live).
- `?endpoint=<id>` : défaut = endpoint par défaut ; inconnu → **404** `{error}`. `/api/metrics` accepte aussi `endpoint=all` (agrégat de tous les endpoints).
- Avant le 1er tick du poller : **503** `{error:'snapshot not ready'}` sur les endpoints snapshot.
- Les endpoints historiques renvoient `source: 'influx' | 'rrd'` — InfluxDB en priorité, **repli RRD Proxmox automatique** (warn loggé, jamais de crash).
- Erreurs : `{ error: string }` avec le code HTTP adapté.

## 2. Endpoints
| Endpoint | Cache | Réponse |
|---|---|---|
| `GET /api/health` | — | `{ status:'ok', mock:boolean, uptimeSec:number }` |
| `GET /api/dashboard` | — | `MultiDashboardSnapshot` (même payload que le push WS) : par endpoint `{ id, name, ok, error, apiVia?, snapshot: DashboardSnapshot }` + **`globalPra: PraReport | null`** (champ **requis** — PRA global cross-endpoints calculé par le poller à chaque tick, `null` si aucun endpoint avec snapshot ; ids de sites préfixés par endpoint — voir skill `hypervision` §11.12) ; 503 si pas prêt. `apiVia` (optionnel) = URL qui a réellement servi les données du dernier poll — définie **seulement si l'endpoint configuré était injoignable** et que le client a basculé sur un autre nœud du cluster (failover, voir skill `general` §4.1) ; absente sinon |
| `GET /api/endpoints` | — | Liste compacte sidebar : `{ id, name, ok, error, nodesOnline, nodesTotal, vmsRunning, vmsTotal, healthScore, healthLabel }[]` |
| `GET /api/audit[?endpoint=]` | — (snapshot live) | **Audit de configuration (best-practices)** — calculé par le **poller** à chaque tick (checks purs `shared/audit.ts`, ponts via `getNetwork` cache 5 min) et posé dans le snapshot WS (`snapshot.audit`) ; la route ne fait que **servir le snapshot** (aucune logique dupliquée, signature `(app, poller)`). Sans `?endpoint=` → `AuditAllResponse { endpoints: AuditEndpointResult[] }` (`AuditEndpointResult = { endpointId, endpointName } & AuditScore`) ; avec `?endpoint=` → `AuditScore` (404 si inconnu). `AuditScore { score, labelKey, counts { crit, warn, info }, checksPassed, checksTotal, findings[] }` — voir skill `audit` |
| `GET /api/capacity?endpoint=` | 5 min/ep | `{ cpu, ram, disk: CapacityForecast, source }` — moyennes journalières 30 j + régression (`buildForecast` : slopePerDay, daysTo80/90, projection 30 j). Disque = stockage VM (`storage_metrics`, pondéré Σused/Σtotal) si disponible, sinon série legacy rootfs |
| `GET /api/node-capacity?endpoint=&node=` | 5 min/(ep,node) | `{ cpu, ram, disk: CapacityForecast, source }` — **capacity planning au NIVEAU NŒUD** (même forme que `/api/capacity`, réemploi `CapacityChartBody`) : `node_metrics` filtré `WHERE node='…'` (pas d'agrégation cross-nœuds), **disk = rootfs du nœud** (`disk_pct`, pas `storage_metrics`). Repli RRD `getRrddata('node')` (cpu ×100, mem/memTotal, rootfs/rootfsTotal). 400 sans `node`, 404 endpoint/nœud inconnu |
| `GET /api/trends?endpoint=` | 5 min/ep | `{ trend7d: {time, cpuPct, ramPct}[], os: {os, count}[], source }` |
| `GET /api/metrics?timeframe=&endpoint=&node=` | 5 min/(ep,tf,node) | `{ timeframe, points: MetricsPoint[], source }` — `timeframe ∈ hour\|day\|week\|month` (sinon **400**) ; `MetricsPoint = { time, cpuPct, ramPct, storagePct:number|null, netInBps, netOutBps }`. Bucket sans série `storage_metrics` → `storagePct: null` (gap). Vue nœud (`?node=`) exclue de la fusion stockage |
| `GET /api/overcommit-risk?endpoint=` | 5 min/ep | Risque dynamique : pire cas = Σ p95 (7 j, `vm_metrics`) par VM running vs capacité physique. `{ insufficientData, cpu:{usagePct,ratio,severity,demandCores,capacityCores}, ram:{…Bytes}, storage:{usagePct,daysTo90,severity}, vms:[{vmid,name,cpuP95Pct,memP95Bytes}] }` — `null`/`na` si aucun historique |
| `GET /api/network-topology` | 5 min/ep | `{ topologies: NetworkTopology[] }` (tous les endpoints ; un endpoint en échec est omis ou servi depuis le cache périmé) |
| `GET /api/storage-inventory` | 5 min/ep | `{ endpoints: [{ endpointId, storages: PveStorage[], vms: StorageVmRef[] }] }` — groupement/agrégats calculés côté client (`shared/storage-inventory`) |
| `GET /api/vm-config?endpoint=&vmid=` | snapshots 5 min/(ep,vmid) ; config 1 h (client PVE) ; live = snapshot courant | `VmDetailResponse { vm: VmSummary (live), config: VmConfigInfo \| null, snapshots: PveVmSnapshot[] }` — 400 si vmid invalide, 404 endpoint/VM inconnu, 503 avant le 1er tick. Snapshots = appel PVE à la demande (`/nodes/{n}/{type}/{vmid}/snapshot`, pseudo-entrée `current` filtrée) |
| `GET /api/node-sensors` | 1 min | `NodeSensorsResponse { timeframe, nodes[], smart: SmartDevice[], sensors: SensorReading[], zfs: ZfsStatus[], failedUnits: FailedUnit[], source:'influx'\|'empty' }` — métriques locales Telegraf (SMART, capteurs, ZFS ARC, unités systemd) depuis la base `raw`, dernier point par clé. **try/catch par section** (une table absente ne vide pas les autres) · `health_ok` arrive en boolean `true` · colonnes ZFS = `arcstats_*` (voir skill `node-sensors`) |
 | `GET /api/node-sensors-history?node=&chip=&feature=&range=month\|year` | 5 min/capteur | `SensorHistoryResponse { node, chip, feature, range, points:{time,temp}[], threshold, thresholdCustom, thresholdFirmware, source }` — historique des valeurs d'un capteur (température °C). **Double source** raw (bucket 10 min, 31 j) + consolidated (15 min, ∞), le raw prime à `t` égal. Série **sparse** (les trous = nœud éteint ne sont pas comblés). Seuils : `threshold` = effectif (perso ≤ firmware), `thresholdFirmware` exposé pour la 2ᵉ ligne si perso. 400 si `node`/`chip`/`feature` absent (voir skill `node-sensors` §3.2) |
| `GET /api/smart-device-history?node=&device=&range=month\|year` | 5 min/disque | `SmartHistoryResponse { node, device, range, points:{time,temp}[], source }` — historique de température d'un DISQUE SMART (`smart_device.temp_c`). Mêmes double source / fusion / série sparse que l'historique capteur. **Sans seuil** (pas de `temp_crit` pour les disques — le front trace la référence fixe 80 °C) ; les points à **0 °C** (pas de sonde) sont exclus. 400 `bad-device` si `node`/`device` absent (voir skill `node-sensors` §3.2) |
| `GET /api/node-system` | **60 s** | `NodeSystemResponse { nodes: NodeSystemRow[], source:'influx'\|'empty' }` — **dernier point par nœud** (fenêtre 10 min) sur `system`+`mem`+`cpu` : load1/5/15, nCpus, uptime, iowait/user/system (cpu-total), swap (total−free), **usage par cœur** (`cpu0..N` = 100−idle−iowait). Vue d'ensemble, carte « Système » + barres CPU par cœur. Rien de tout cela dans l'API PVE (voir skill `node-sensors` §3.3) |
| `GET /api/node-diskio?node=&timeframe=` | 5 min/(node,tf) | `NodeDiskioResponse { timeframe, node, devices: NodeDiskioRow[], source:'influx'\|'insufficientData' }` — I/O **par device physique** (disques entiers seuls : dm-/loop-/md-/sr-/ram exclus SQL, **partitions filtrées côté TS**) ; débits = Δ counter / bucket (`diskioRateSql` : `date_bin`+`MAX` puis `LAG`, delta négatif reboot → **null**), `busyPct` = Δ`io_time`/durée 0–100 (iostat), `awaitMs`. `timeframe ∈ hour\|day\|week\|month` → **400** sinon, 400 sans `node` |
| `GET /api/vm-diskio?endpoint=&vmid=&timeframe=` | 5 min/(ep,vmid,tf) | `VmDiskioResponse { timeframe, vmid, series: VmDiskioSeries[], source:'influx'\|'insufficientData'\|'noMapping' }` — I/O **par disque de la VM** : mapping `dm-N` → LV PVE depuis `dm_names` (plugin `exec` Telegraf ; `parsePveMapperName`, VM QEMU seulement) ; 1 requête `diskioRateSql` sur les dm de la VM. `noMapping` = table absente (agent à (re)déployer — **pas une erreur HTTP**, l'UI le dit), `insufficientData` = mapping présent mais aucun LV dm (stockage non LVM-thin). 400 vmid/timeframe invalide, 404 endpoint inconnu |
| `GET /api/node-net?node=&timeframe=` | 5 min/(node,tf) | `NodeNetResponse { timeframe, node, interfaces: NodeNetIface[], rows: NodeNetRow[], source:'influx'\|'insufficientData' }` — trafic réseau **par interface hôte** (table `net`, plugin Telegraf, `netRateSql` = bucket+LAG des counters `bytes_recv`/`bytes_sent`, delta négatif → null) : NICs physiques + ponts vmbr*, **vnet\*/tap\*/veth\*/lo exclus SQL** (le trafic tap = vue VM, double-comptage). `interfaces` = liste des interfaces du nœud (API PVE `GET /nodes/{n}/network` via `nodeEndpoint(ctx, poller, node)` — dispo même sans mesures) : `{ name (nom PVE), kernels: [name, ...altnames] (candidats noyau — le joint passe sur n'importe lequel), kind:'bridge'\|'nic'\|'other'\|'firewall', active, firewall?: NodeNetFwInfo { vmid, ifIndex, role } }` + union des kernels vus seulement dans les mesures : les `fw*` du pare-feu PVE y sont **décodées** par `parsePveFwIface` (`fw(br|ln|pr)<vmid>(i|p)<n>` → `kind:'firewall'` + métadonnées `firewall`), les autres en `kind:'other'` (dégradation douce — jamais de faux décodage) (`buildNodeNetIfaces`, pur, exporté, testé). Table absente → `insufficientData` (avec `interfaces` renseigné — agent à (re)déployer). 400 sans `node` ou timeframe invalide |
| `GET /api/vm-net?endpoint=&vmid=&timeframe=` | 5 min/(ep,vmid,tf) | `VmNetResponse { timeframe, vmid, series: VmNetSeries[], source:'influx'\|'insufficientData'\|'noMapping' }` — trafic **par carte de la VM** (l'API PVE = agrégat seulement) : config PVE → cartes net0/net1 (bridge, **MAC**) × `net_if_mac` (plugin `exec` Telegraf, fenêtre 1 h) → MAC → tap hôte, 1 `netRateSql` sur les tap résolus. `noMapping` = tables absentes, `insufficientData` = VM hors snapshot / aucune carte lue ; MAC non trouvée (VM arrêtée) = série `hostIface=null`, points vides. 400 vmid/timeframe invalide, 404 endpoint inconnu (voir skill `node-sensors` §3.3/§4/§6) |
| `GET /api/node-temps?node=&timeframe=` | 5 min/(node,tf) | `NodeTempsResponse { timeframe, node, series: NodeTempSeries[], source:'influx'\|'insufficientData' }` — températures **par chip** (table `sensors`, `max(temp_input)` par (chip, bucket), `temp_input IS NOT NULL` SQL). Jauges (pas de LAG). 400 sans `node` ou timeframe invalide (voir skill `node-sensors` §3.4) |
| `GET /api/smart-temps?node=&timeframe=` | 5 min/(node,tf) | `SmartTempsResponse { timeframe, node, series: SmartTempSeries[], source:'influx'\|'insufficientData' }` — températures **par disque** SMART (table `smart_device`, `max(temp_c)` par (device, bucket), **`temp_c > 0` SQL** = les disques sans sonde sont exclus). `SmartTempSeries { device, model, points }` — modèle joint par 2ᵉ requête glissante 1 h. 400 sans `node` ou timeframe invalide (voir skill `node-sensors` §3.4) |
| `GET /api/zfs-arc?node=&timeframe=` | 5 min/(node,tf) | `ZfsArcResponse { timeframe, node, points: ZfsArcPoint[], source:'influx'\|'insufficientData' }` — ZFS ARC (table `zfs`) : `ZfsArcPoint { t, sizeBytes, maxBytes, hitRatePct }`. Jauges `max(arcstats_c)` / `max(arcstats_c_max)` + hit rate = Δ compteurs **dans le bucket** (max−min, pas de LAG) via `zfsHitRatePct` (`null` si compteurs 0/reset) — `hitRatePct: null` = série hit rate à masquer côté front (pattern ProxMenux, jamais de série inventée). 400 sans `node` ou timeframe invalide (voir skill `node-sensors` §3.4) |
| `GET /api/node-system-history?node=&timeframe=` | 5 min/(node,tf) | `NodeHostHistoryResponse { timeframe, node, points: NodeHostHistoryPoint[], source:'influx'\|'insufficientData' }` — **load 1/5/15 + nCpus** (table `system`) **+ swap** (table `mem` : utilisé = `max(total)−min(free)`, null si total=0). 2 requêtes isolées fusionnées (`mergeHostHistory`) — une table absente ne fait pas perdre l'autre. Jauges `max` du bucket (pas de LAG). Consommé par les widgets `load` + `swap` du Monitor nœud v4. 400 sans `node` ou timeframe invalide (voir skill `node-sensors` §3.4) |
| `GET /api/user-config` | — | `{ userId, config: UserConfig \| null, lastUpdated }` — **personnalisation d'interface par utilisateur** (layouts des grilles vue d'ensemble v2 / monitors v3 + bibliothèque de widgets). `UserConfig { schemaVersion, pages, lastUpdated }` (types + `parseUserConfig` dans `shared/user-config.ts`). **Session obligatoire** (guard global), `userId` = `req.authUser.id` (jamais de l'URL) — chacun lit SA config, aucun rôle requis |
| `PUT /api/user-config` | — | corps = config **complète** validée par `parseUserConfig` (stricte) → 200 `{ userId, config, lastUpdated }` ou **400 `bad-config`** (schemaVersion/structure invalides). Écriture atomique `data/user-configs/<userId>.json` (tmp+rename, corrompu → null au read) |
| `DELETE /api/user-config` | — | réinitialisation (retour aux layouts par défaut des pages) → `{ userId, config: null, lastUpdated: null }` |
| `GET /api/influxdb` | — | **Module InfluxDB 3 Core** (santé de la base de métriques) : `{ enabled, ping, version, databases: {name,retention}[], write: {enabled,queueDepth,enqueued,flushed,dropped,failedBatches,lastDropAt,lastErrorAt}, query: {lastQueryMs,lastQueryAt,lastQueryError}, fileEstimate: {chunkDays,chunkFiles,yearFiles,fileLimit,headroom:'ok'\|'warn'\|'crit'}, archive: {lastArchivedTs,archiveDir,fileCount,totalBytes}, canAct }`. `version` = best-effort (`/api/v3/server-info` — 404 sur certaines versions → `null`). `databases` via `GET /api/v3/configure/database?format=json` (clé **`iox::database`**, sans rétention → `null`). `canAct` = admin OU membre d'un groupe de `INFLUX_ACTION_GROUPS` (défaut `Administrateurs,Exploitations`). 404 `influx-disabled` si InfluxDB désactivé/mock |
| `GET /api/influxdb/history?range=24h\|7d\|30d` | 5 min/range | `InfluxHistoryResponse { range, points: {t,queueDepth,dropped,queryMs,enqueued}[] }` — santé InfluxDB depuis la self-telemetry `influxdb_self` (base raw, 1 ligne/tick poller) : buckets 5 min (24h) / 15 min (7d) / 1 h (30d). Sert le mini-graphe du widget overview + les 4 graphiques de la page /influxdb. 400 `bad-range` sinon |
| `POST /api/influxdb/actions/flush` | — | flush immédiat de la file d'écriture → `{ ok, queueDepth, flushed }`. **Sans body** (ne pas envoyer `Content-Type: application/json` vide — `FST_ERR_CTP_EMPTY_JSON_BODY`) |
| `POST /api/influxdb/actions/archive/run` | — | cycle d'archivage maintenant (consolidated → CSV) → `{ ok, archived: {from,to} }`. Sans body |
| `POST /api/influxdb/actions/archive/reset` | — | réinitialise l'état d'archivage (`data/archive-state.json`) → `{ ok }`. Sans body |
| `POST /api/influxdb/actions/export` | — | export CSV d'une table `consolidated` sur période → `{ ok, file, rows }`. Body `{ table, from, to }` (timestamps s). Fichier dans `INFLUX_ARCHIVE_DIR` |
| `POST /api/influxdb/actions/database/recreate` | — | **destructif** : supprime puis recrée la base (données perdues, rétention immuable en Core) → `{ ok }`. Body `{ name, retention? }` (ex. `31d`) |
| `POST /api/influxdb/actions/database/drop` | — | **destructif** : supprime la base → `{ ok }`. Body `{ name }` |
| `POST /api/influxdb/actions/table/drop` | — | **destructif** : supprime une table → `{ ok }`. Body `{ db, table }` |

> **Actions InfluxDB** : guard groupes (`/api/influxdb/actions/*` → 403 `influx-actions-group` si ni admin ni membre d'un groupe de `INFLUX_ACTION_GROUPS`). Chaque action loggée `influxdb.action` dans le journal d'audit admin (`data/admin-audit.jsonl`). Validation noms `/^[a-zA-Z0-9_-]+$/`. Le tick ne bloque jamais sur InfluxDB (ping 60 s fire-and-forget). RFC : `docs/plan-module-influxdb.md`.

## 3. WebSocket `/ws`
- Pousse `{ type:'snapshot', data: MultiDashboardSnapshot }` **toutes les 5 s** (rythme du poller) + immédiatement au connect.
- Aucun message client→serveur ; le web se reconnecte en backoff exponentiel (1 s → 30 s max).
- La config `overcommit.json` est aussi poussée en WS (defaults côté web avant le 1er push).

## 4. Repli InfluxDB → RRD (historique)
- `influxReady = influx.enabled && !mock` ; erreur de requête ou série vide → warn loggé + RRD Proxmox (`source:'rrd'`).
- Buckets par timeframe : `hour`=1 min/1 h, `day`=5 min/24 h, `week`=1 h/7 j (base **raw**) ; `month`=1 j/30 j (base **consolidated**).
- Filtre cluster : `COALESCE(cluster, '<default>') = '<epId>'` (lignes legacy sans tag → endpoint par défaut) ; `endpoint=all` → `1=1`.
- Sémantique disque : `storage_metrics` (stockage VM, pondéré par capacité) ≠ `disk_pct` (rootfs nœud).

## 5. Ajouter un endpoint
1. Créer `packages/server/src/modules/<name>/routes.ts` avec `registerXxx(app, ctx, poller)` (même signature).
2. L'enregistrer dans `modules/index.ts` (tableau `modules`).
3. Types partagés → `@proxmox/shared` (types.ts ou fichier dédié) — jamais dupliqués serveur/web.
4. Endpoint lourd → cache 5 min + repli InfluxDB→RRD s'il lit l'historique.
5. Côté web : consommer via `ctx.api` (client REST partagé, `core/api/apiClient`) — jamais de HTTP/WS propre depuis un plugin.
